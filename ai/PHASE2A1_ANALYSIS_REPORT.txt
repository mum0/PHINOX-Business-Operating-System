1. KPISERVICE SIGNATURES (from 46_KpiService.js)
═══════════════════════════════════════════════════════════════════════════════

1.1 calculateKpi(kpiId, periodType, refDate)
────────────────────────────────────────────
  Parameters:
    • kpiId     (string, required) — e.g. 'FIN-01', 'SALE-01'
    • periodType (string, optional) — defaults to KPI's own period or MONTHLY
    • refDate    (Date/string, optional) — reference date for period calculation

  Returns:
    • KPI Record Object:
      {
        id:           'KPI-XXXXXXXXX',
        kpiId:        'FIN-01',
        name:         'Revenue',
        value:        12345.67,
        period:       '2024-01',
        date:         '2024-01-01',
        sheet:        'KPI Results',
        createdAt:    Date
      }

  Side Effects:
    • Calculates KPI value using FinanceService/OrderService/etc.
    • Upserts result to KpiRepository (idempotent)
    • Logs to Logger

  Error Handling:
    • Missing kpiId → throws validation error
    • Unknown kpiId → throws notFound error
    • Calculator failure → catches, logs, returns 0

1.2 calculateAll(periodType, refDate)
─────────────────────────────────────
  Parameters:
    • periodType (string, optional)
    • refDate    (Date/string, optional)

  Returns:
    • {
        results: [
          { kpiId: 'FIN-01', status: 'ok',    value: 12345 },
          { kpiId: 'FIN-02', status: 'ok',    value: 6789 },
          { kpiId: 'FIN-03', status: 'error', value: 0 }
        ],
        errors: [
          { kpiId: 'FIN-03', status: 'error', message: '...' }
        ]
      }

  Behavior:
    • Iterates ALL 81 KPI definitions
    • Calls calculateKpi for each
    • Collects results and errors
    • Returns summary object

  Performance:
    • Calculates 81 KPIs → expensive (many sheet reads, service calls)
    • NOT recommended for simple 4-KPI dashboard

1.3 getDashboardKpis()
──────────────────────
  Parameters: NONE

  Returns:
    • Dashboard Object (all 81 KPIs):
      {
        'FIN-01': { name: 'Revenue',      category: 'FINANCE',     unit: '$', value: 12345, period: '2024-01', calculatedAt: Date },
        'FIN-02': { name: 'COGS',         category: 'FINANCE',     unit: '$', value: 6789,  period: '2024-01', calculatedAt: Date },
        'SALE-01': { name: 'Total Orders', category: 'SALES',       unit: '#', value: 100,   period: '2024-01', calculatedAt: Date },
        ... (81 total)
      }

  Behavior:
    • Uses CURRENT date (now) as reference
    • Determines period key based on each KPI's default period
    • Reads from KpiRepository (cached results)
    • Does NOT calculate fresh values
    • Returns 0 for KPIs not yet calculated

  Limitations:
    • NO period filtering — always current period
    • NO refDate parameter
    • Returns stale data if KPIs not pre-calculated

1.4 calculateCategory(category, periodType, refDate)
────────────────────────────────────────────────────
  Parameters:
    • category   (string) — 'FINANCE', 'SALES', etc.
    • periodType (string, optional)
    • refDate    (Date/string, optional)

  Returns:
    • Array of KPI Records for that category only

  Use Case:
    • Calculate all FINANCE KPIs or all SALES KPIs
    • Still calculates multiple KPIs

2. HOW REVENUE / EXPENSES / PROFIT / ORDERS ARE CALCULATED
═══════════════════════════════════════════════════════════════════════════════

2.1 REVENUE (FIN-01)
────────────────────
  Calculator:  function(dates) { return _round(FinanceService.getRevenue(dates.start, dates.end), 2); }
  Source:      FinanceService.getRevenue(startDate, endDate)
  Returns:     Total revenue for the period (number)

2.2 EXPENSES — MAPPING DECISION NEEDED
────────────────────────────────────────
  KpiService does NOT have a "Total Expenses" KPI.

  Available finance KPIs:
    • FIN-02: COGS (Cost of Goods Sold)
    • FIN-03: Gross Profit = Revenue - COGS
    • FIN-04: Net Profit = Revenue - COGS - Operating Expenses

  Options for "expenses":

    Option A: Use FIN-02 (COGS)
      → expenses = COGS only
      → Does NOT include operating expenses
      → Label should be "COGS" not "Expenses"

    Option B: Derive from Revenue - Net Profit
      → expenses = Revenue - Net Profit
      → Includes COGS + Operating Expenses
      → Matches business definition of "Total Expenses"
      → Requires calculating FIN-01 AND FIN-04 first

    Option C: Add custom calculation
      → Call FinanceService.getProfitAndLoss() directly
      → pnl.operatingExpenses or pnl.cogs
      → Bypasses KpiService (architecturally wrong)

  RECOMMENDATION: Option B
    • Most accurate business representation
    • Uses existing KpiService calculations
    • No architectural violation

2.3 PROFIT (FIN-04)
────────────────────
  Calculator:  function(dates) { var pnl = FinanceService.getProfitAndLoss(dates.start, dates.end); return _round(pnl.netProfit, 2); }
  Source:      FinanceService.getProfitAndLoss(startDate, endDate).netProfit
  Returns:     Net Profit for the period (number)

2.4 ORDERS (SALE-01)
────────────────────
  Calculator:  function(dates) { return OrderService.totalOrdersByDateRange(dates.start, dates.end); }
  Source:      OrderService.totalOrdersByDateRange(startDate, endDate)
  Returns:     Count of orders in period (integer)

3. PERIOD VALUES & REFDATE HANDLING
═══════════════════════════════════════════════════════════════════════════════

3.1 FRONTEND PERIOD VALUES
──────────────────────────
  From UI_Index_Patched.html:
    <select id="kpiPeriod">
      <option value="monthly">Monthly</option>
      <option value="quarterly">Quarterly</option>
      <option value="yearly">Yearly</option>
    </select>

  Values sent: 'monthly', 'quarterly', 'yearly'

3.2 KPISERVICE PERIOD VALUES
────────────────────────────
  From KpiSchema (inferred from code):
    S.PERIOD = {
      DAILY:     'DAILY',
      WEEKLY:    'WEEKLY',
      MONTHLY:   'MONTHLY',
      QUARTERLY: 'QUARTERLY',
      YEARLY:    'YEARLY'
    }

  Mapping required:
    Frontend        → KpiService
    ─────────────────────────────
    'monthly'       → S.PERIOD.MONTHLY   (or 'MONTHLY')
    'quarterly'     → S.PERIOD.QUARTERLY (or 'QUARTERLY')
    'yearly'        → S.PERIOD.YEARLY    (or 'YEARLY')

3.3 REFDATE HANDLING
────────────────────
  Frontend sends: refDate as ISO string (e.g. '2024-01-15') or empty string

  KpiService._getPeriodDates(periodType, refDate):
    • Calls S._periodStart(periodType, refDate)
    • Calls S._periodEnd(periodType, refDate)
    • If refDate is null/undefined → defaults to today

  Empty string handling:
    • KpiService uses new Date(refDate) internally
    • new Date('') → Invalid Date → likely defaults to today
    • Safe to pass empty string or null

5. PROPOSED uiGetKPIs REDESIGN
═══════════════════════════════════════════════════════════════════════════════

5.1 RECOMMENDED APPROACH: calculateKpi × 4
───────────────────────────────────────────
  Instead of calculateAll (81 KPIs) or getDashboardKpis (no period support),
  call calculateKpi 4 times for the specific KPIs needed.

  Proposed implementation:

    function uiGetKPIs(params) {
      try {
        _requireAuth(PERMISSIONS.DASHBOARD_READ);

        // Map Frontend period values to KpiSchema values
        var periodMap = {
          'monthly':   KpiSchema.PERIOD.MONTHLY,
          'quarterly': KpiSchema.PERIOD.QUARTERLY,
          'yearly':    KpiSchema.PERIOD.YEARLY
        };
        var periodType = periodMap[params.period] || KpiSchema.PERIOD.MONTHLY;
        var refDate = params.refDate || null; // null = today

        // Calculate specific KPIs
        var revenueRecord = KpiService.calculateKpi('FIN-01', periodType, refDate);
        var cogsRecord    = KpiService.calculateKpi('FIN-02', periodType, refDate);
        var profitRecord  = KpiService.calculateKpi('FIN-04', periodType, refDate);
        var ordersRecord  = KpiService.calculateKpi('SALE-01', periodType, refDate);

        // Derive total expenses = Revenue - Net Profit
        var revenue = _toNumber(revenueRecord.value);
        var profit  = _toNumber(profitRecord.value);
        var expenses = revenue - profit; // Total Expenses (COGS + Operating)

        return {
          success: true,
          data: {
            revenue:  revenue,
            expenses: _round(expenses, 2),
            profit:   profit,
            orders:   _toNumber(ordersRecord.value)
          }
        };
      } catch (e) {
        return { success: false, error: e.message };
      }
    }

5.2 WHY THIS APPROACH
─────────────────────
  ✓ Period filtering supported (periodType + refDate)
  ✓ Uses KpiService (architecturally correct)
  ✓ Only 4 KPIs calculated (efficient)
  ✓ Fresh data (calculates on demand)
  ✓ Matches Frontend expected shape
  ✓ Error handling per KPI (one failure doesn't break all)
  ✓ Idempotent (calculateKpi upserts safely)

5.3 ALTERNATIVE APPROACHES REJECTED
────────────────────────────────────
  ❌ getDashboardKpis()
    • No period filtering
    • Returns stale cached data
    • Returns 81 KPIs (overkill)

  ❌ calculateAll(periodType, refDate)
    • Calculates all 81 KPIs (very expensive)
    • Returns different shape ({results, errors})
    • Requires complex transformation

  ❌ Direct sheet reading (current patch)
    • Bypasses KpiService (architecturally wrong)
    • Wrong sheet name, wrong type values
    • No period filtering

7. RISKS & REGRESSIONS
═══════════════════════════════════════════════════════════════════════════════

7.1 IDENTIFIED RISKS
────────────────────
  Risk 1: KpiSchema not available
    • uiGetKPIs references KpiSchema.PERIOD
    • KpiSchema is defined in 44_KpiSchema.js
    • If not loaded before UI_Server, will throw ReferenceError
    • MITIGATION: Ensure load order in GAS (KpiSchema before UI_Server)

  Risk 2: FinanceService/OrderService failures
    • calculateKpi catches calculator errors and returns 0
    • But if FinanceService itself is missing, throws before calculation
    • MITIGATION: Error handled by try/catch in uiGetKPIs

  Risk 3: Period mapping mismatch
    • Frontend sends 'monthly', KpiSchema expects 'MONTHLY'
    • Mapping object handles this, but if KpiSchema values differ → fails
    • MITIGATION: Verify KpiSchema.PERIOD values in 44_KpiSchema.js

  Risk 4: Negative expenses
    • expenses = revenue - profit
    • If profit > revenue (e.g. due to other income), expenses becomes negative
    • MITIGATION: Math.max(0, revenue - profit) to ensure non-negative

  Risk 5: Performance
    • 4 × calculateKpi = 4 service calls + 4 repository upserts
    • Acceptable for dashboard load
    • If slow, consider caching or pre-calculation

7.2 REGRESSIONS
───────────────
  • None expected — new implementation replaces broken workaround
  • Frontend behavior unchanged
  • Response shape identical
