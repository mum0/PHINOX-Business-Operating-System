❌ المشكلة #1: callServer يستخدم fn.apply()

الوصف

دالة callServer في الكلينت تستخدم نمط fn.apply(runner, args) لاستدعاء دوال السيرفر. هذا النمط فيه مشكلة مع google.script.run — الـ proxy functions بتاعة GAS ممكن ما تتعاملش مع .apply() بشكل سليم في كل الحالات.

// الكود الحالي (مشكلة محتملة) var fn = runner[action]; if (typeof fn === 'function') { var args = Array.prototype.slice.call(arguments, 1); fn.apply(runner, args); // ← ممكن ما يشتغلش! }

الأثر

  • لو .apply() فشلت، الـ Promise ما بيحصلش resolve ولا reject أبداً
  • النتيجة: الـ loading spinner يدور للأبد بدون ما يعرض بيانات أو خطأ
  • ده يفسر بالضبط مشكلة "يفضل يحمل"

الحل

// الحل الآمن: استدعاء مباشر بدون .apply() var fn = runner[action]; if (typeof fn === 'function') { var args = Array.prototype.slice.call(arguments, 1); fn(args[0], args[1], args[2], args[3], args[4]); } else { reject(new Error('Server function "' + action + '" not found')); }

لماذا ده آمن: google.script.run.uiGetDashboardKpis() بيتعامل معاه GAS كـ proxy call مباشر. بدون .apply()، كل حاجة بتشتغل.

❌ المشكلة #2: 13 Service غير موجودة في الريبو

الوصف

UI_Server.js يعتمد على 13 Service object على السيرفر. ولا واحدة منهم موجودة في ملفات المشروع (لا في .js ولا في .gs). لو أي واحد فيهم مش موجود في GAS، كل الدوال اللي بتستخدمه هتThrow.

// الأمثلة: KpiService.getDashboardKpis() // ← مش موجود في الريبو! InventoryService.getInventory() // ← مش موجود! OrderService.getOrders() // ← مش موجود! CustomerService.getAll() // ← مش موجود! FinanceService.getStats() // ← مش موجود! TaskService.getTasks() // ← مش موجود! MktService.getRecords() // ← مش موجود! SocService.getRecords() // ← مش موجود! SatisfactionService.getRecords() // ← مش موجود! NPSService.getRecords() // ← مش موجود! BOMService.getBOM() // ← مش موجود! StockMovementService.getMovements() // ← مش موجود! SaleService.getSales() // ← مش موجود!

الأثر

لو KpiService مش موجود، دالة uiGetDashboardKpis() هتThrow:

ReferenceError: KpiService is not defined

GAS هيلقط الخطأ ده للـ withFailureHandler في الكلينت، لكن الكلينت الحالي ما عندهش Console Logging — فالمستخدم مش هيشوف الخطأ.

الحل

شغّل أداة التشخيص (?page=diagnose) وشوف أي Services ناقصة. أداة التشخيص بتعرض قائمة بالـ Services الموجودة والناقصة.

⚠️ المشكلة #3: getCurrentMember() ترجع null

الوصف

getCurrentMember() في 13_Permissions.js ليها "fail closed" policy — ترجع null في أي حالة غير طبيعية. وده يخلي _requireAuth() ترمي Error في كل مكان.

الحالةالنتيجةالكود
الايميل فاضي من SessionnullLine 430-433
شيت Members مش موجودةnullLine 441-444
شيت Members فاضيةnullLine 446-449
الايميل مش موجود في الشيتnullLine 480-484
الايميل موجود لكن Status ≠ ActivenullLine 464
الايميل مكرر أكثر من مرةnull (security block)Line 474-478

الأثر

  • uiGetCurrentUser() → بيرجع { success: false, error: "..." } ← ده OK، بيظهر خطأ
  • كل دوال البيانات (uiGetDashboardKpis الخ) → بتستدعي _requireAuth() → بتThrow Error
  • الكلينت بيCatch الخطأ لكن ما بيظهرش رسالة واضحة — السبنر بيفضل يدور

الحل

  1. افتح شيت Members في Spreadsheet
  2. تأكد إن إيميلك موجود في العمود D (EMAIL) بالظبط
  3. تأكد إن الـ Status في العمود F = Active
  4. تأكد إن ما فيش إيميل مكرر
  5. شغّل ?page=diagnose وشوف النتيجة

⚠️ المشكلة #4: الأخطاء بتحدث بس ما بتتعرض

الوصف

في الكلينت، لما دالة بيانات تفشل (مثلاً uiGetDashboardKpis)، الـ .catch() بيحدث الـ DOM بـ error message. لكن:

  • لو حصل Error في callServer نفسها (قبل ما الـ Promise يتعمل) — الأخطاء ما بتتعرضش
  • لو google.script.run مشتغلش — لا alert ولا console.log
  • الـ Auth overlay ممكن تفضل ظاهرة من غير ما توضح السبب

الحل

استخدم نسخة callServer المحسّنة بالـ Logging (في ملف UI_JS_Core.html الجديد).

✅ المشكلة #5: لا يوجد Logging

الوصف

دالة callServer الحالية ما عندها أي console.log. لما أي حاجة تفشل، المستخدم مش بيعرف ليه. أداة التشخيص (DIAGNOSE.html) وحالة uiDiagnose.gs بيحلوا ده.

📋 خطة التنفيذ

الخطوة 1: تشخيص سريع (5 دقائق)

  1. ارفع DIAGNOSE.html و uiDiagnose.gs على GAS
  2. افتح ?page=diagnose في المتصفح
  3. اضغط "Run All Tests"
  4. النتائج هتقولك بالضبط فين المشكلة

الخطوة 2: إصلاح callServer (أهم إصلاح)

غيّر fn.apply(runner, args) لـ fn(args[0], args[1], args[2], args[3], args[4]) في UI_JS_Core.html. ده الملف المعدل جاهز في gas_deploy/.

الخطوة 3: تأكد من Members sheet

  1. افتح الـ Spreadsheet
  2. شيت Members لازم يكون فيها 12 عمود على الأقل
  3. إيميلك لازم يكون في العمود D (EMAIL)
  4. Status لازم يكون Active في العمود F

الخطوة 4: تأكد من إعدادات النشر

  • Execute as: Me (مش User accessing)
  • Who has access: Anyone أو Your domain
  • افتكر تعمل New deployment بعد أي تعديل في السيرفر

الخطوة 5: تأكد من Services

لو التشخيص أظهر إن Services ناقصة، ده معناه ملفات .gs في الغير موجودة في مشروع GAS. لازم تتأكد إن كل الـ *Service.gs ملفات مرفوعة.
